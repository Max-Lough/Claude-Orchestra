# WORK ORDER — Interface Artisan (E5), WO-12c casting trial — c-03

## Goal

Build a static, dependency-free signup form with labeled inputs and
statically-present inline validation messages. No browser is available in
this harness, so "validation" here means the error-message markup exists
and is correctly wired via `aria-describedby` — not that it dynamically
toggles.

## Output

Exactly one file: **`form.html`** — a standalone, valid HTML document, with
its CSS in a single inline `<style>` block in the `<head>`. No other files.

## Fixed structure (reproduce exactly)

A `<form id="signup-form">` containing exactly 3 fields, each a `<label
for="...">` + `<input>` pair wired to a `<p class="error-message">` via
`aria-describedby`, plus a submit button:

| input id | label text | input type/name | `aria-describedby` | error message id | error message copy |
|---|---|---|---|---|---|
| `full-name` | Full name | `type="text"` `name="fullName"` | `full-name-error` | `full-name-error` | Please enter your full name. |
| `email` | Email address | `type="email"` `name="email"` | `email-error` | `email-error` | Please enter a valid email address. |
| `password` | Password | `type="password"` `name="password"` | `password-error` | `password-error` | Password must be at least 8 characters. |

Followed by `<button type="submit">Create account</button>`.

## Fixed palette (hex — reproduce exactly)

- `label { color: #111827; background-color: #ffffff; }`
- `.error-message { color: #7f1d1d; background-color: #fee2e2; }`

## Constraints (do not)

- Do **not** load any external CSS or JS.
- Do **not** use inline event-handler attributes (`onclick=`, `onsubmit=`,
  etc.) anywhere — including on the submit button.
- Do **not** include any `http://` or `https://` literal URL.
- Do **not** rely on native browser validation UI as the mechanism being
  tested — the error-message elements must be present in the static markup
  regardless (this is a generation-only, no-browser exercise).

## Mechanical acceptance checks (by name)

`node c/check.js --order c-03 --file form.html` runs:

1. `well-formedness (tag-balance)`
2. the 4 forbidden-content checks (the inline-handler check matters most
   here — a validation-message form is exactly where an `onsubmit=` or
   `onclick=` temptation shows up)
3. the 8 `requiredStructure` checks named in `c/checks/c-03.json` (the form
   id, each label+input pair, each error message, the submit button)
4. `contrast: label text on form background`,
   `contrast: error-message text on error-message background` (both ≥
   4.5:1)

15 minutes.
